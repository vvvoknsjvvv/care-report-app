## 〇概要

- 介護現場での事故・ヒヤリハット報告の管理をweb上で一元管理するシステム。
- スマートフォンでの使用を想定し、スタッフが直感的に操作できるようにUIを調整して作成。

### 〇制作背景
前職の介護施設では、介護事故が起きると発見者の職員が「利用者の安全確認・処置」→「責任者・利用者家族の報告」→「事故報告書の作成」までするため、責任の重圧と心理的負担が掛かり業務の中で事故報告書の作成が特に苦しい業務だった。

また、紙での管理のため、過去の報告書を活用する機会がなく、会議などでは直近2か月程度の報告書しか使われない課題があった。

こうした負担や課題を軽減するために本システムでは
- 業務フローをシステム上で「報告書作成」→「事後対応・再発防止策」と業務を分けることで、連絡の前に情報を整理してから報告ができるように。
- 活用されずらい過去の報告書はソート機能を実装することで、会議中に過去の報告書を参照しながら再発防止策を検討できるように。

※重大性の高い介護事故は行政のフォーマット・書式での提出が必要なため、このシステムでは対象外。

※管理者アカウントからの承認機能もケアマネージャーとの再発防止策の作成があるため、口頭・対面での確認を想定して未実装。

### 〇プロンプトエンジニアリング

開発にあたり、Gemini3.1Proを使用してコーディング。

cliでの生成も検討しましたが、ブラックボックス化やSSDの劣化、学習面を考慮し普段使いしているGeminiを使用。

コードから出力せず、要件定義から始め壁打ちを開始。開発中のエラーはログ、画面を提供して解決。開発後半からMarkdownをプロンプトに組み込んで指示。

### 〇起動方法

**Java 11以上のインストールが必須**

- Windows の場合  
  フォルダ内の 「起動.bat」をダブルクリック  
  停止時は ctrl+cで「バッチ ジョブを終了しますか (Y/N)?」が表示されるので、yで停止。
- Linux / Mac の場合  
  ターミナルを開く  
  カレントディレクトリを本作品データが入ったディレクトリに移動  
  コマンド入力 $ `java -jar carereport.jar`  
  停止はターミナルから ctrl+c を入力

### 〇ログイン画面

springboot起動後、http://localhost:8081/login からアクセス。

### 〇H2データベース確認ページ

  JDBC URL: jdbc:h2:mem:testdb

  User Name: sa

  Password: （空欄）でログイン

http://localhost:8081/h2-console からアクセス。

### 〇ポート番号を変更するファイル

application.propertiesファイルの server.port=\*\*\*\* を変更。

**変更時はMavenで再度パッケージ化**

### 〇アカウント権限

- 管理者アカウント権限
  - すべての報告書の閲覧・作成・編集・削除が可能。
  - すべての利用者の閲覧・作成・編集・削除が可能。
  - すべての事後対応・再発防止策の閲覧・入力が可能。
  - 報告書詳細から完了済みの事後対応・再発防止策が編集可能。

- 一般アカウント権限
  - すべての報告書の閲覧・作成が可能。
  - すべての利用者の閲覧が可能。
  - すべての事後対応・再発防止策の閲覧が可能。
  - 自分が作成した報告書のみ、事後対応・再発防止策の入力が可能。
